## 〇、关于"90% 投中率"

这个承诺给不了，任何人都给不了。理由有三条：

1. 该刊未公布录用率，我查不到可信统计，无法反推概率；
2. 外审专家个人偏好、当期栏目余量、同期竞争稿件都不可控；
3. 本稿最大的短板——**缺一组用真实数据做的对比实验**——需要作者导出积分流水才能补，不是改写能解决的。

本次评审做到的是：**把所有"会被扣分且改得动"的地方全部清掉**。按下面第五节把实验补上，才是把命中率往上抬的唯一实质动作。

## 三、审核专家（计算机应用 / 软件工程视角）

### R1　方法贡献的呈现强度不足 —— **未完全解决**

《计算机系统应用》的拒稿理由"建议投普及类期刊"，翻译过来是：**读着像工程报告**。本刊外审大概率给出同样判断。

现稿的方法主张有三条（分段权重分配、时间衰减前置、状态机引擎），但只有第一条给了对比（表1），且是**理论系数对比而非实验对比**——它只说明四种方法系数不同，没说明**用了本文方法之后人才排名发生了什么变化**。这是"提出了一个模型"和"验证了一个模型"的区别。

已做的补救：新增**表5 本文系统与同类工作的对比**（评价对象 / 核心方法 / 多作者成果分配 / 成果时效处理 / 量化与画像同源 / 审批流程支持），把本文在文献坐标系里的位置摆明确。这能缓解但不能替代实验。

**根治办法见第五节。**

### R2　结论段自曝短板 —— 已解决

改前原文：

> α 与 λ 目前取自经验值，**尚缺少敏感性分析的支撑**。后续将补齐这部分实验……

审稿人读到"作者自己承认核心参数没有依据"，基本就是退修起步。但正文 3.3 节其实**已经给了制度依据**（α = 0.7 对应事业单位近三年考核口径；λ = 0.14 对应 5 年聘期），是结论段的表述把自己写死了。

改后：

> α 与 λ 依据事业单位近三年考核口径与 5 年聘期设定，制度依据明确，但其取值区间对人才排名的影响程度仍有待更大样本的敏感性分析验证。

同时把局限性整理为三条（活跃度≠质量、参数敏感性待验、映射矩阵需跨机构重标定），这是标准写法，不是掩盖。

### R3　"德尔菲法"名不副实 —— 已解决

3 名专家做两轮打分，**称德尔菲法会被质疑**。德尔菲法通常要求 15–50 名专家、多轮匿名反馈至收敛。

改为如实表述：「由本中心 3 名具有高级职称的科研管理专家经两轮独立打分与组间反馈修正确定……受机构规模限制，参与标定的专家人数偏少，该矩阵反映的是本中心的评价导向，跨机构应用时需重新标定」。

### R4　表4 增幅缺口径说明 —— 已解决

申报单量 192 → 1420（7.4 倍）归因于"参与度提升"，但线下台账本身存在漏登记，**两个数并非同口径**。审稿人一定会问。

已补：明确区分「不同口径」的申报单量与「同口径」的审核周期 / 超时件数 / 差错率三项，后者才具可比性。主动交代比被问出来好。

### R5　公式与自洽性 —— 复核通过

7 个公式逐一验算：

- 式(1) `Sᵢ = S_total × (0.2 + 0.8δᵢ,₁ + 0.6δᵢ,₂ + 0.3δᵢ,₃)`：i=1→1.0，i=2→0.8，i=3→0.5，i≥4→0.2 ✓ 与表1、正文三处一致
- 式(4)(5) 两级衰减分工明确（式(4) 处理周期内、式(5) 承担跨周期），**无重复计算** ✓
- 式(6) 无二次衰减，与式(4) 前置设计自洽 ✓
- 式(7) 归一化至 [20,100]，`C_max = C_min` 时取 60 的退化处理已交代 ✓
- 交叉引用完整：图 1–2、表 1–5、式 (1)–(7) 全部在正文有指代
- 参考文献 30 条全部被引用，无悬挂条目

## 四、专业科研人员（科研管理 / 卫生信息视角）

### S1　名义分值制的立论是本稿最有价值的部分

各作者所得之和可达标准积分 2.5 倍，这在文献计量学里是"不守恒"的异端，但作者给出的理由站得住：**疾控机构要的是鼓励多科室协作，不是精确切分学术信用**；且"挂名"风险由年度上限封顶 + 第 4 作者不计入职称口径两项**制度约束**承担。

建议保持这个立场，不要被审稿人劝回守恒制——这恰恰是本文区别于纯文献计量方法的地方。已在结论中明确表述为"管理导向下的取舍，其代价由制度约束承担，而非由算法本身消化"。

### S2　标签准确率评估是全稿最扎实的实验

270 人中随机抽 90 名、3 名专家独立标注、三人一致为金标准、Kappa 0.81、P/R/F1 = 88.0%/84.1%/0.86。**这是一组方法规范、可复现的真实实验**，应当在摘要和结论里更突出，已在结构化摘要中单列。

### S3　数据边界

本稿度量的是**科研活跃度**而非成果质量，与同行评议互补而非替代——这一条已写入结论局限性。在"破四唯"语境下这句话很重要，能挡掉"又一个数数的系统"的批评。

## 七、把命中率真正抬上去的一步（**强烈建议**）

补两组实验，数据全部来自现有积分流水，**系统不用上线，纯离线计算**。

```bash
python3 论文审稿/实验/分配方法对比实验.py works.csv --topn 10,30 --out 表6.txt
python3 论文审稿/实验/参数敏感性分析.py records.csv --now 2025 --out 表7.txt
```

两个 CSV 的导出 SQL：

```sql
-- works.csv : work_id,author_id,author_rank,is_corresponding,std_points
SELECT r.work_id, r.author_id, r.author_rank, r.is_corresponding, i.std_points
FROM points_record r JOIN points_item i ON r.item_id = i.id
WHERE r.status = 'approved';

-- records.csv : user_id,tag,points,year
```

跑出来能直接补三张表：

| 表 | 内容 | 回应的审稿意见 |
|---|---|---|
| 四种分配方法的 Spearman 秩相关 | 本文方法有没有把排序搞乱 | R1「只有理论对比」 |
| Top-N 人员重合度 + 协作型/独立型排名变动 | 本文方法**改变了什么**、方向对不对 | R1 核心 |
| α / λ 敏感性曲线 | 参数取值稳健性 | R2「参数依据」 |

**这是把稿子从"工程报告"变成"方法+实现"最低成本的一步：两张 CSV 换三张表。** 数据给我，我把表和这一节的正文一起写好。
