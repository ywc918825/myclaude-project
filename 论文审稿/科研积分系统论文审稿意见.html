M3必改 · 学术硬伤

5.3 节能力得分算法的推导链是断的

论文给出三个步骤，但第三步和前两步用的是两条互不相干的数据通路：

① C(d,u) = Σ_t [ W(t,u) × m(t,d) ] ← 输入是标签权重 W ② C'(d,u) = (C - C_min)/(C_max - C_min) × 100 ← 归一化 ③ C_final(d,u) = Σ_k(s_k·w_k) / Σ_k(w_k) ← 输入变成了成果积分 s_k

被称为"最终得分"的 ③ 根本没有用到 ①② 的结果。也就是说，5.3 节实际上给了两套彼此独立的能力得分公式，而正文把它们当成一条链在叙述。这是审稿人会明确指出的逻辑问题。

修改方案 A（推荐）

把时间衰减前移到标签权重层：在 5.2 节计算 W 时，对每笔积分先乘衰减因子

W(t,u) = α · Σ_i [ s(i,u) · e^(−λ(t_now − t_i)) · w_i ] / Z + β · W_old(t,u)

然后 ①→② 保持不变。这样 5.2 与 5.3 自然衔接，得分链条统一，公式数量还少了一条。

修改方案 B

保留 ③，但明确把 ①② 定位为"标签维度得分（供标签云使用）"、③ 为"能力维度得分（供雷达图使用）"，并说明两者用途与数据来源的差异。

还有一个会被追问的设计取舍：③ 是加权平均（分母有 Σw_k），意味着成果越多得分不一定越高——多而旧的成果会把均值拉低，这与"积分激励产出"的导向相冲突。若确实要用加权平均，请在文中解释理由；若想体现产出总量，应改为加权求和 Σ(s_k · w_k)。

M4必改

5.2 节标签权重公式量纲不一致

W(t,u) = α · Σ_i [ s(i,u) × w_i ] + β · W_old(t,u)　　α=0.7, β=0.3

第一项是"积分 × 贡献系数"的累加，无上界，量纲是分；第二项是上一周期的权重，应当是 [0,1] 区间的无量纲量。两个不同量纲的量按 α+β=1 加权相加，数学上不成立。后文"对权重低于 0.1 的标签自动清理"进一步说明作者默认 W ∈ [0,1]，但公式产出的并不是这个范围。

修改方案

对行为项做归一化。令 s̃(i,u) = s(i,u)/S_max（S_max 取该周期全中心该标签下的最高行为积分，或该标签的年度积分上限），并约束 Σ_i w_i = 1，则：

W⁽ᵏ⁾(t,u) = α · Σ_i [ s̃(i,u) · w_i ] + (1−α) · W⁽ᵏ⁻¹⁾(t,u)，　α = 0.7

同时点明这是一阶指数加权移动平均（EWMA），α = 0.7 对应记忆长度约 1/(1−α) ≈ 3.3 个周期。这样"近期占 70%、历史占 30%"才有数学依据，也顺带回答了"参数怎么定的"。

加分做法：补一个小实验——取 α ∈ {0.5, 0.6, 0.7, 0.8, 0.9}，看人才排名的 Spearman 秩相关如何变化，说明 0.7 的稳健性。这是把"经验取值"变成"实验标定"最省力的办法，审稿人很吃这一套。

M5必改 · 最易被质疑

多作者积分分配的权重和大于 1，且 Kronecker δ 只是形式包装

S_i = S_total × (0.2 + 0.8·δ(i,1) + 0.6·δ(i,2) + 0.3·δ(i,3))

展开后就是一张查找表：第 1 作者 1.0、第 2 作者 0.8、第 3 作者 0.5、第 4 及以后 0.2。用 Kronecker δ 写出来并不增加算法内涵，反而容易让审稿人觉得是在包装。

更要紧的是：n = 4 时全体作者合计拿到 2.5 倍 S_total，n = 6 时 2.9 倍。积分总量随作者数膨胀，客观上激励"多挂名"，与"破四唯、重实质贡献"的立意相反。这是本文最可能被质疑的一点。

M6必改

min-max 归一化的三个缺陷，图 4.2 已经暴露了

  • 分母为零。当某维度全中心得分相同（新设维度、冷门维度）时 C_max = C_min，公式除零。需加保护：分母为 0 时取 50，或加 ε 平滑。
  • 极值敏感、大量零分。图 4.2 的雷达图里"工作经历 / 学术影响力 / 团队建设 / 科普贡献"全部是 0%，雷达图退化成尖刺。全中心最低分者在每个维度恒为 0，画像失去区分度，也打击积极性。建议改用分位数归一化，或 min-max 后线性映射到 [20, 100]。
  • 纵向不可比。C_min / C_max 随人员流动与年度产出漂移，同一人跨年度的画像无法比较，与"动态反映最新能力状态"的目标直接冲突。建议固定基准（如以上线首年的分布为基准）或改用绝对分档。

把这三条主动写进论文并给出处理方式，是明确的加分项——说明作者清楚自己方法的边界。
